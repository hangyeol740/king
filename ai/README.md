# 강화학습 AI

## 다양한 선택을 위한 v8 학습

- 성향 6종(balanced/bold/cooperative/trader/builder/investigator)의 5개 입력값을 게임마다 정하고 유지합니다. 성향은 작은 선택 편향이며 승패 학습을 대신하지 않습니다.
- 동일 행동 종류의 후보 수로 확률을 보정합니다. 후보가 많다고 거래·제작만 선택되는 쏠림을 줄이며 PPO 업데이트에도 동일한 분포를 사용합니다.
- 카드 소량·저점 중심·영구 카드 보존 후보를 추가합니다. 전체 카드 조합을 열거하지 않습니다.
- 학습/배포 모두 자기 손패·공개 정보로 동일 인벤토리 왕복 제작과 반복 가격 변경을 걸러냅니다. 한 반복 행동 단계는 최대40회 후 완료를 선택합니다. 사람의 게임 규칙은 바꾸지 않습니다.
- 3~6인 중심으로 시민/반란군/중립 추가와 주교만·상인만·동시·일반 중립 구성을 섞습니다. 동시에 행동할 수 있는 사람의 처리 순서도 섞습니다.
- 현재 모델·이전 세대·협력/공격/제작/거래 기본 전략 상대를 섞어 PPO로 학습합니다. 보상은 최종 승리+1/패배-1이고 거래 횟수 보상 등은 없습니다.
- 평가는 진영/성향별 승률, 단계별 행동 분포·최다 행동 비율·엔트로피를 저장합니다. 승률 표본만으로 사람에게 재미있다고 단정하지 않습니다.
- 시험 모델 `models/diverse-pilot.json`, 추가 모델 `models/diverse-candidate.json`을 따로 저장합니다. 기존 배포 모델을 자동 덮어쓰지 않습니다.

### 이번 실행 결과

- 시험32판 + 추가500판 + 추가5,000판 = 새 구조 **5,532판**, 누적 **2,023,928회 행동**을 학습했습니다. `models/diverse-trained.json`에 저장했습니다. 이전 v3 모델의 800판은 이전 지식이며 이 학습 횟수에 합산하지 않습니다.
- 별도300판 혼합 전략 평가: **163승/300판(54.3%)**, 왕53/73·시민35/83·반란군75/81·주교0/18·상인0/21·일반중립0/24. 평가 구성과 직업 비율이 달라 전체 승률만으로 우열을 단정할 수 없습니다.
- 첫 낮 행동의 최다 선택 비율40.1%, 마지막 낮53.8%, 저녁86.7%입니다. 첫 낮 다양성은 개선됐지만 저녁 지명수배 고착과 중립 직업의 부족한 승리 경험이 남았습니다.
- **배포 모델 `models/policy.json`은 보존**했습니다. 새 모델은 검증 후보이며 사람 상대 재미를 확인하지 않은 상태입니다. 추가 학습은 주교/상인 승리까지 가는 정상 게임 중간 상태 수집과 직업별 표본 평가를 우선해야 합니다.
- 독립 평가 상세: `models/diverse-evaluation.json`.

```bash
node ai/train.js --transfer models/policy.json --episodes 32 --players 3,4,5,6 --batch 8 --eval-games 12 --epochs 1 --output models/diverse-pilot.json --seed 740
node ai/train.js --resume models/diverse-pilot.json --episodes 500 --players 3,4,5,6 --batch 16 --eval-games 80 --epochs 2 --output models/diverse-candidate.json --seed 741
```

v8 파일은 `--resume`, v2~v7 파일은 `--transfer`를 사용합니다. 추가 옵션은 `--entropy`(기본.025), `--learning-rate`(기본.0005), `--epochs`(기본2)입니다.

## 바로 플레이

`models/policy.json`은 실제 셀프플레이로 학습한 신경망 모델입니다. 서버 시작 시 읽고 CPU로 추론합니다. 대기실에서 방장이 **AI 추가**를 두 번 누르면 사람 1명 + AI 2명으로 플레이할 수 있습니다. AI는 왕·시민·반란군·중립을 무작위 배정받고 모든 단계에서 자동으로 행동합니다.

학습 중이 아닌 웹 서버에서는 외부 API·Python·GPU가 필요 없습니다. 모델을 포함해 Render에 배포하면 사용자 컴퓨터가 꺼져 있어도 동작합니다.

## 방식

- **PPO(클리핑된 정책 경사) + actor/critic 신경망 + GAE + Adam**, 모두 Node.js에서 실행합니다.
- 관측 → 은닉층 32개(tanh) → 행동 특징의 선호도 → 적법한 후보에 대한 softmax 확률 → 선택.
- critic은 관측에서 예상 결과를 추정합니다. 승리한 참가자는 +1, 나머지는 -1의 최종 보상을 받습니다. 주교는 인원별 종교반란 목표(4인 1일·5인 2일·6인 이상 3일) 또는 철혈의 검으로 승리합니다.
- 학습 중 주로 현재 모델끼리 플레이하며 일부 참가자는 기본 전략 상대 또는 이전 모델을 사용합니다.
- 기본 전략 상대(`baseline`)는 학습·평가용입니다. 게임의 AI 참가자는 저장한 **학습 모델**을 사용합니다. 모델이 없거나 규칙/크기가 맞지 않으면 AI 추가를 비활성화합니다.
- 학습 게임도 실제 `lib/game.js` 엔진을 사용하므로 웹게임과 별도 규칙을 유지하지 않습니다.

### 정보와 행동 범위

AI 정책은 `view(room, playerId)` 개인별 상태만 입력받습니다. 상대 손패·숨겨진 진영·밤 누적점수·다른 사람 제출량은 입력하지 않습니다. 본인의 손패, 날짜, 반란 성공 횟수, 직접 본 검사와 공개 지원 기록 등을 사용합니다.

모델이 선택하는 후보는 모든 행동 종류와 대상, 제작 1개/가능한 최대 수량, 카드 0장/전체/절반/종류별 묶음/점수 조건을 만족하는 묶음, 세금의 카드 종류 조합입니다. **가능한 모든 카드 조합을 학습하는 구조는 아닙니다.** 카드 선택을 적법한 유한 후보로 제한해 작은 CPU 모델로 학습·추론할 수 있게 했습니다. 후보 중 최종 선택은 학습된 가중치와 확률이 결정합니다.

기억은 공개 기록·개인 검사 기록을 요약한 특징입니다. 언어모델이나 재귀 신경망이 아니며 디스코드 대화를 이해하지는 않습니다. 초기 모델은 진영별 성능 차이가 크며 중립의 철혈 승리는 아직 어려워합니다.

## 현재 규칙과 모델 평가

현재 정책 버전은 7입니다. 상인·익명 상점·동시 구매·돈 중재·저녁 진열 및 제작·32종 제작법과 신규 영구 카드2종을 반영했습니다. 상인 AI만 자신의 돈을, 주교 AI만 자신의 교단영향력을 관측합니다. 공개 상품 정보는 입력하지만 타인 돈·손패·비공개 투표·상인 신원은 관측하지 않습니다. 5인 학습 게임은 주교와 상인을 함께 포함합니다.

서버는 기존 v2~v6 모델을 메모리에서 v7 구조로 이전하여 사용할 수 있습니다. 같은 의미의 관측·행동 가중치를 보존합니다. `/api/ai`의 `adaptedRules`가 true이면 기존 규칙 학습 모델을 이전한 상태이며 새 상인 규칙 추가 학습은 아닙니다.

현재 모델의 새 규칙 학습 횟수는 metadata.episodes, 이전 모델에서 가져온 지식은 metadata.transferredFrom에서 확인합니다. 별도 평가 결과는 `models/evaluation.json`에 있습니다. 모델을 추가 학습하면 평가 기록도 새로 생성하세요.

## 학습 명령

새 모델을 3/4/5인 게임으로 학습:

```bash
npm run ai:train -- --episodes 3000 --players 3,4,5 --eval-games 120 --seed 42
```

v7 모델에서 **추가 학습**:

```bash
npm run ai:train -- --resume models/policy.json --episodes 3000 --players 3,4,5 --eval-games 120
```

기존 v2~v6 모델을 새 규칙으로 이전하여 추가 학습하려면 아래를 사용합니다. 새 규칙 학습 횟수는 0부터 별도로 기록합니다.

```bash
npm run ai:train -- --transfer models/policy.json --episodes 800 --output models/next-policy.json
```

`--transfer`와 `--resume`은 동시에 사용할 수 없습니다. v2~v6 파일은 `--transfer`, v7 파일은 `--resume`을 사용하세요.

기본 경로를 덮어쓰지 않고 별도 모델에 저장:

```bash
npm run ai:train -- --resume models/policy.json --episodes 1000 --output models/next-policy.json
```

- `--episodes`: 이번 실행에서 학습할 게임 수(이어서 학습할 때 기존 횟수에 추가)
- `--players`: 쉼표로 구분한 3~8인 게임 구성. 기본 `3,4,5`.
- `--batch`: 업데이트 배치당 게임 수. 기본 16.
- `--eval-games`: 학습 전후 각 상대에 대해 평가할 게임 수. 기본 60.
- `--seed`: 신경망 초기화·행동 샘플링·학습 셔플 시드. 게임 카드 생성은 기존 암호학적 난수를 사용하므로 전체 실험이 동일하게 재현되지는 않습니다.

학습 진행 중 주기적으로 모델과 옵티마이저 체크포인트를 저장합니다. Ctrl+C를 한 번 누르면 현재 게임/배치를 마친 후 저장합니다. 같은 모델 경로를 사용하면 덮어쓰므로, 이전 모델을 유지하려면 `--output`으로 별도 경로를 지정하세요.

## 결과물

- `models/policy.json`: 추론 가중치와 실제 누적 학습 횟수·행동 수·학습 전후 평가·손실 기록. **배포에 포함**합니다.
- `models/policy.json.checkpoint.json`: 추가 학습용 Adam 상태. 없어도 가중치부터 이어서 학습할 수 있습니다. 배포에는 필요 없고 `.gitignore`에서 제외합니다.

모델과 체크포인트 저장 이후 결과 로그를 확인하세요. 모델 파일이 존재한다고 강한 AI라는 뜻은 아니며, 실제 학습 횟수와 평가를 확인해야 합니다.

## 독립 평가

```bash
npm run ai:evaluate -- --games 300 --players 3,4,5 --opponent baseline --seed 740
npm run ai:evaluate -- --games 300 --opponent random
npm run ai:evaluate -- --games 300 --output models/evaluation.json
```

각 게임에서 평가할 AI 한 명의 좌석과 진영을 무작위로 정하고 나머지는 지정한 상대를 사용합니다. 전체 승률과 **왕·시민·반란군·중립별 승률**을 함께 봅니다. 왕과 시민은 승리 조건을 공유하므로 무작위 승률이 50%라고 가정하면 안 됩니다. 상대·인원·진영 표본에 따라 달라지며, 소수 판 평가의 수치를 사람 상대 승률로 해석하면 안 됩니다.

## 서버 적용

새 모델 저장 후 `npm start`로 서버를 재시작해야 가중치가 갱신됩니다. 실행 중에 학습하지 않습니다.

- `AI_MODEL_PATH`: 모델 파일 경로. 기본 `models/policy.json`.
- `AI_DELAY_MS`: AI 행동 간 지연. 기본 750ms, 최소 50ms.
- `/api/ai`: 모델 가용 여부·학습 횟수·학습일을 반환합니다. 가중치와 비밀 정보는 반환하지 않습니다.
- 방마다 예약 타이머 한 개로 순차 실행합니다. 사람이 전부 오프라인이면 봇을 멈추고 재접속 시 계속합니다.
- 한 방의 AI는 최대 8명. 인원·날짜·진영 계산에는 사람과 AI를 모두 포함합니다.

게임 규칙이나 관측·후보 구조가 바뀌면 `RULESET`/버전을 갱신하고 맞는 모델을 다시 학습해야 합니다.

## 무료 배포

GitHub 업로드에 `models/`와 그 안의 **`policy.json`**도 포함하세요. `ai/`, `lib/`, `public/`, `server.js`, `package.json`, `package-lock.json`도 최신 파일로 올리고 Render를 재배포합니다. 모델은 서버에서만 읽으며 무료 서버에서 장시간 학습할 필요는 없습니다.
