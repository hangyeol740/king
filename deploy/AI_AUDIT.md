### I01 — 기습 차례로 반란군 정체 노출 [재현, 심각]

### S03 — 채널별 계획/기억의 직접 혼합 [미재현]

## 평가·체크포인트: 기존 승률 해석 수정 필요

### E01 — 서로 다른 상대 이름이 같은 balanced 전략을 실행 [재현, 심각]
`evaluate`의 분기는 opponent가 mixed일 때만 style을 읽고 나머지 문자열은 전부 balanced로 호출합니다. 따라서 aggressive/cooperative/builder/trader 라벨의 평가가 실제로는 같은 균형 전략입니다. 앞서 보고한 '8종 상대 토너먼트'는 라벨대로 실행된 실험이 아니며 재평가가 필요합니다.

### 코드 확인
- `opponents`는 최대6개 저장하지만 opponentPool은 `[0]` 한 개만 사용합니다. '과거 좋은 모델 여러 개와 대결'이 구현됐다는 설명은 부정확했습니다.
- baseline에 reserve/보존형이 없고 builder는 자원얻기 고정입니다. 독립적인 보존 전략이 아닙니다.
- scorePolicy의 previous가 매번 bestPolicy로 바뀌어 기준 상대가 달라지는데 예전 bestScore와 직접 비교합니다.
- 초기 모델을 finalist에 넣지 않고 마지막 bestPolicy만 추가하므로 초기 모델 대비 최종 승자가 나쁜지 안정적으로 검증하지 못합니다. 동일 모델 중복 후보도 가능.
- 토너먼트1위가 roleFloor 미달이면2위의 통과 후보를 찾지 않고 기존 best를 유지합니다.
- 핵심 진영 표본이 부족하면 제외되고 빈 목록은 minimumRole=1이 됩니다. 데이터 부족을 통과로 간주할 수 있음.
- 초반에 선택된 bestPolicy에도 전체 시도 completed를 metadata.episodes로 씁니다. **1,020판은 총 학습 시도 누적이며 선택된 가중치에1,020판 업데이트가 모두 적용됐다는 뜻은 아닙니다.**
- 저장 모델이 bestPolicy일 때 optimizer는 현재 trainer의 값을 씁니다. 최종 토너먼트가 다른 과거 후보를 선택하면 가중치/옵티마이저가 맞지 않을 수 있습니다.
- 후보·상대 풀·최고 optimizer·RNG 상태를 재개 파일에 저장하지 않습니다. timeout 뒤 resume은 동일 실험을 정확히 이어가는 것이 아닙니다.
- 배치 주기와 evalEvery가 맞지 않으면60~120판 평가가 실제 해당 시점에 실행되지 않을 수 있습니다.
- crypto 카드/진영 난수 때문에 같은 평가 시드가 동일한 출발/덱을 보장하지 않습니다.
- 시민·중립 승률은 상대 동료의 정책에 의존합니다. 단순 전체 승률·절대18% 하한만으로 역할 균형 개선이라고 단정하지 못합니다.
- 승률 신뢰구간·고정 검증 세트·다중 후보 선택의 과적합 통제가 없습니다.
- `ai/compare.js`, `ai/evaluate.js` 기본 모델 경로가 현재 배포 모델과 다릅니다. 명시 경로 없이 실행하면 다른 모델을 평가할 수 있습니다.

따라서 기존1,020판 모델이 작동하지 않는다는 뜻은 아니지만, 앞서 제시한 승률로 '더 똑똑함/팀 구분/사람다운 대화'가 입증됐다는 해석은 취소해야 합니다.

## 실제 사람 기록·학습

- D01: live-learning 생성 시 saved.humanActions를 복원하지 않음 [재현].
- recordHumanAction은 act 후 phase/round를 읽어 행동이 일어난 단계가 아니라 다음 단계를 집계할 수 있음.
- 개인정보를 제외한 통계만 입력에 넣는 경로와 원문 서버 기록은 다릅니다. 후자는 임의 원문을 보관하며 구조 검증/보관량 제한이 부족합니다.
- online capture는 실제 행동 입력의 target/recipe/stock 등 전체 의미를 action 요약에 보관하지 않음. chosen=-1이면 features에서 실제 선택을 복구할 수 없어 '모든 선택을 학습 가능하게 기록'은 아직 아님.
- candidates에 없는 기권/무승부와 임의 수량은 chosen=-1로 모방 학습에서 제외됨.
- 행동 이벤트에 policy/rules version이 없어 차원은 같지만 보상/규칙이 다른 기록을 혼합할 수 있음.
- style은 질문률·문자수·일부 구어체 정규식뿐입니다. 이는 말투 미세조정/인간 대화 이해 학습이 아닙니다.
- live-learning은 한 의도값을 계속 유지해 다른 단계의 판단도 오래된 사람 발언에 귀속될 수 있음.
- plan 참조를 기록하지만 JSON 재시작 후 별개 객체가 되므로 상태 동기화의 신뢰성 검사가 필요.
- 모방 학습은 패배 행동에도 양의 advantage .25를 주며, 양질 플레이 선별/역할 균형/holdout 평가가 없음.
- export-dialogue는 같은 사용자의 이전 발언을 self 필터로 버리고 다른 발언을 모두 user로 둠. 완전한 다자 대화 학습 표현이 아님.
- 학습 원문 내보내기와 파인튜닝 제출/LLM 가중치 업데이트는 다릅니다. 자동 미세조정은 구현되지 않았음.
- 서버 events.jsonl 파일은 재배포 임시 디스크에서 사라질 수 있음. Supabase archive는 개별 행 저장만 있고 재학습용 전체 다운로드/스타일 통계 복원은 로컬 파일만 읽음.
- 경험 큐는 메모리 무제한·원격 실패 시 자동 재시도 없음. archive 실패해도 파일은 남지만 일관성 추적/재전송 도구가 없음.
- outcome 기록 전 플래그를 세워 원격 저장 실패 후 재호출로 복구되지 않음.

## 수정 우선순위

1. 기습 정체 누출과 기권/결투 교착 해결. 잘못된 평가 라벨과 보상 즉시 분리.
2. 개인 관찰/알려진 팀/직업별 목표 단일 정의. 무의미한 동료 피해는 후보/평가에서 억제하되 규칙상 허용 전략은 명시 근거로 처리.
3. 약속을 상대·단계·목표점수·조건·취소/수정·이행 결과를 가진 계약으로 교체. bluff는 실행 의무와 분리.
4. 사람 채팅 trigger를 상태 observation이 덮어쓰지 않게 큐 분리. 게임 상태 변화는 행동/발언 각각 유효성 판단.
5. 오류/폐기/침묵/실행불일치를 AI별 진단으로 노출. API 실험과 운영 로그 구분.
6. 보상을 개인별 결과/행동 비용으로 검증. 공격 횟수 보상 제거. 고정 상대 풀/역할별 평가 재실행.
7. 정확한 checkpoint+optimizer+후보+상대풀 재개 지원. 기존 모델 승률 재평가 후 교체 여부 결정.
8. 행동 기록의 정확한 재현성과 버전·복구·표본 품질 검사 후 사람 기록 모방 학습 평가.

이 감사에서 추가한 것은 재현 스크립트와 보고서입니다. 발견된 문제들을 모두 고쳤다고 표시하지 않습니다. 미배포 단일 결정 수정은 종전 작업 상태로 남겼고, 새 폭탄 조건 등 다른 변경을 덮어쓰지 않았습니다. 커밋·푸시·배포하지 않았습니다.
