# 왕국과 반란

PC 브라우저에서 방을 만들고 6자리 코드로 참가하는 실시간 비공개 카드 게임입니다. 서로 다른 와이파이에서도 **인터넷에 배포한 동일한 주소**로 접속하면 함께 플레이합니다. 대화는 디스코드를 사용합니다.

## 로컬 실행

Node.js 20 이상이 필요합니다.

```bash
npm install
npm start
```

브라우저에서 **http://localhost:3000**을 엽니다. 한 PC에서 테스트할 때는 서로 다른 브라우저나 독립 시크릿 세션을 사용하세요. 같은 브라우저의 같은 사이트는 하나의 플레이어로 복귀하도록 설계되어 있습니다.

```bash
npm test
```

## 무료 인터넷 배포: Render

Render의 무료 **Web Service**를 사용합니다. WebSocket을 지원하므로 별도의 소켓 서버는 필요 없습니다. 정적 사이트 서비스로는 게임 서버를 실행할 수 없습니다.

1. 이 폴더의 코드를 자신의 GitHub 저장소에 올립니다. `node_modules`, `.data`, `.env`는 올리지 않습니다.
2. [Render](https://dashboard.render.com/)에 로그인합니다.
3. **New → Blueprint**에서 저장소를 연결하면 `render.yaml` 설정을 사용할 수 있습니다.
4. 직접 **New → Web Service**로 만드는 경우 아래 설정을 사용합니다.

   | 항목 | 값 |
   | --- | --- |
   | Runtime | Node |
   | Build Command | `npm ci` |
   | Start Command | `npm start` |
   | Instance Type | **Free** |
   | Health Check | `/health` |

5. 배포가 끝나면 Render가 발급한 `https://서비스이름.onrender.com` 주소를 공유합니다.
6. 한 명이 방을 만들고 방 코드나 화면의 **초대 링크 복사**로 친구들을 초대합니다.

배포하려면 본인의 GitHub·Render 계정에서 저장소 연결이 필요합니다. 이 프로젝트에는 배포 설정이 포함되어 있으며, 아직 공개 서버 주소가 발급된 상태는 아닙니다.

### 무료 호스팅과 재접속

- 브라우저 새로고침·일시적인 네트워크 끊김: 같은 브라우저의 저장된 비밀 복귀 토큰으로 직업·손패·차례를 복구합니다. 접속 끊김은 자동 패스하지 않습니다.
- 동일 플레이어가 다른 탭에서 복귀하면 가장 최근 연결이 활성화됩니다.
- 로컬 서버는 `.data/rooms.json`에 게임을 저장하므로 정상적인 서버 재시작에도 복구합니다. `DATA_DIR` 환경변수로 저장 위치를 지정할 수 있습니다.
- **Render 무료 서버의 파일 저장소는 일시적**입니다. 서버 재배포·재시작·휴면 시 기존 방 데이터가 사라질 수 있습니다. 이 경우 새 방을 만들어야 합니다. 무료 서버는 접속이 없는 상태가 15분 이어지면 휴면하며 첫 접속 시 약 1분이 걸릴 수 있습니다.
- 서버 재시작을 넘어서 영구 복구가 필요하면 외부 영구 데이터베이스 연결을 추가해야 합니다.

공식 안내: [무료 서비스](https://render.com/docs/free), [WebSocket](https://render.com/docs/websocket).

## 구현한 규칙

### 진영과 승리

- 최소 3인. 3인은 왕·시민·반란군 각 1명. 4인은 중립 1명 추가.
- 5인 이상은 네 진영을 1명씩 기본 배치하고 방장이 추가 인원의 진영을 설정합니다. 왕은 항상 1명입니다.
- 시작 시 무작위 진영 배정. 왕 공개, 본인 진영만 확인. 반란군끼리는 서로 확인합니다.
- 3인 7일 / 4인 6일 / 5인 이상 5일. 반란 성공 누적 3일에 즉시 반란군 승리. 마지막 저녁 종료까지 2일 이하이면 왕·시민 승리.
- 마지막 날은 밤 없이 종료합니다. 중립은 현재 승리 조건·고유 능력이 없습니다.
- 철혈의 검을 보유하면 해당 진영 즉시 승리. 왕 또는 시민이면 왕·시민 공동 승리. 획득법이 미정이므로 현재 랜덤·제작에서 나오지 않습니다.

### 아침

시작 손패 5장. 첫날부터 왕이 아침 행동을 선택하고 재분배합니다.

- 밤의 반란력을 전원에게 공개. 0점이면 중재 불가.
- **중재:** 왕 선포 → 왕 이외 전원 지원 확정(0장 가능) → 왕 제출 → 합계 비교. 보병 2점, 장교 7점, 병기 17점. 중재력이 반란력 **이상**이면 성공. 지원은 왕의 손패를 거치지 않으며 모두 일회용 소모. 선포·제출 취소 불가.
- 중재 실패 또는 중재 미선택 시 반란 성공 1일. 성공·실패·중재 미선택 모두 판정 후 반란점수 초기화. 세 번째 반란 성공이면 나머지 행동 없이 즉시 종료.
- **공개처형:** 4인 이상, 왕 이외 1명을 지목. 손패 전부 버림, 탈락하지 않음.
- **원정:** 왕 필참, 다른 플레이어 자유 참가. 참가자는 0장 이상 제출 가능. 공격력 **11 이상**이면 전원 4장, **21 이상**이면 전원 9장. 불참자도 지급. 칼·마법·병기·영구 카드 및 보병 1점·장교 3점 사용 가능.
- 아침 행동 후, 23장 초과 손패는 무작위로 **22장**까지 축소. 정확히 23장은 유지.
- 이후 각자 비공개 재분배 수락/거절: 수락하면 손패 전부 버리고 새로 **12장**, 거절하면 유지. 왕도 선택.

### 낮

왕 이후 무작위 고정 순서로 세 바퀴. 행동과 카드 변화는 비공개이며, 현재 차례만 공개합니다. 패스 버튼은 없습니다.

1. **거래 / 채집(자원 4장) / 랜덤 카드 3장**
   - 거래 거절 시 신청자 차례 종료.
   - 거래 수락 시 양쪽이 비공개로 줄 카드를 선택·확정한 뒤 동시에 교환. 0장 허용. 상대 카드·수량은 교환 전까지 숨김.
2. **제작 / 사냥**
   - 제작은 원하는 만큼 반복·연속 가능, 완료 버튼으로 종료. 재료가 없는 경우에도 제작을 선택하고 완료 가능.
   - 사냥은 한 번. 칼·마법·병기·영구 공격 카드만 사용. 공격력 **6 이상**이면 4장, 실패 보상 없음. 0장 사냥도 실패로 처리.
3. **전체 교체 / 랜덤 2장 / 전원 손패 수 확인 / 타인 카드 1장 확인**
   - 전체 교체는 기존 장수만큼 새로 생성.
   - 손패 수는 확인 당시 기록만 제공.
   - 타인 카드 확인은 무작위 1장, 확인자에게만 표시. 손패 0장이면 없음 표시. 대상에게 별도 알림 없음.

### 저녁과 밤

- **세금:** 왕 제외 전원이 자신이 선택한 2장을 왕에게 납부. 부족하면 전부, 0장이면 0장 납부.
- **지명수배:** 왕 이외 1명 검사. 반란 또는 선동이 있으면 손패 전부 버림. 왕에게 구체적인 두 카드 존재 여부 제공, 전원에게 혐의 여부·처분 공개. 병기는 검사 조건에 포함하지 않음.
- **시민지원:** 왕 제외 전원에게 랜덤 3장.
- **밤:** 반란군마다 반란·선동·병기를 원하는 만큼 확정 제출. 0장 허용. 합계·제출자·카드는 밤에 비공개, 다음 아침 총점 공개.

### 카드와 제작

랜덤 카드는 매번 독립 확률로 생성합니다. 공용 덱이 소진되는 방식이 아닙니다.

| 반란 | 18% | 3 | — | — |
| 선동 | 7% | 8 | — | — |
| 병기 | 1% | 20 | 17 | 8 |
| 칼 | 15% | — | — | 1 |
| 마법 | 4% | — | — | 4 |

| 장교 | 5% | — | 7 | 원정만 3 |
| 영구 칼 | 0% | — | — | 2 |
| 영구 마법 | 0% | — | — | 5 |

일반 사용 카드는 성공·실패 관계없이 소모됩니다. 영구 공격 카드는 사냥·원정 한 번에 각 카드당 한 번씩 사용하고 손패에 남습니다. 영구 카드는 일반 칼로 취급하지 않으며 재분배·몰수·제작 재료 사용 시 소모됩니다.

## 구조

- `lib/game.js`: 서버 전용 게임 규칙, 차례 검증, 개인별 비공개 상태 생성
- `server.js`: HTTP·Socket.IO, 방과 복귀 토큰, 상태 저장
- `public/`: PC 화면·카드 선택 UI·재연결
- `test/`: 승패 경계·비밀 정보·거래·재접속 검증
- `render.yaml`: Render 무료 Web Service 배포 설정

클라이언트는 행동 요청만 보내고 서버가 본인 손패·대상·차례·단계를 검증합니다. 다른 사람의 손패·숨겨진 진영·복귀 토큰은 클라이언트로 보내지 않습니다. 현재 서버 한 인스턴스 기준입니다.
